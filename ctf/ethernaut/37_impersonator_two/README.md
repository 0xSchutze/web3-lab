# Level 37: ImpersonatorTwo

**Target:** [ImpersonatorTwo.sol](./ImpersonatorTwo.sol)
**Exploit Script:** [exploitScript.s.sol](./exploitScript.s.sol)

## Vulnerability
The contract relies on `ECDSA.recover` to verify signatures created by the owner. However, during the contract's initialization, the owner signs two different messages (`switchLock` and `setAdmin`) using the **exact same nonce (k-value)**. This cryptographic flaw (ECDSA Nonce Reuse) allows an attacker to mathematically recover the owner's private key from the two public signatures and their corresponding message hashes.

## Key Concepts
- **ECDSA (Elliptic Curve Digital Signature Algorithm):** The standard signature algorithm used in Ethereum.
- **Nonce (k-value) in ECDSA:** A random, ephemeral value that MUST be unique for every signature generated by a specific private key.
- **k-value Reuse:** If two different messages are signed with the same private key and the *same* k-value, the resulting signatures will share the same `r` value.
- **Private Key Recovery:** When `r` is identical across two signatures ($s_1$ and $s_2$) for two known message hashes ($z_1$ and $z_2$), the private key ($d$) can be calculated using simple modular arithmetic.

## Root Cause
The root cause is a cryptographic operational failure by the owner (or the system generating the signatures). By failing to generate a cryptographically secure, pseudo-random `k` value for each signing operation, the owner exposed the relationship between their private key and the public signatures. 

The math for recovery is:
1. $k = \frac{z_1 - z_2}{s_1 - s_2} \pmod n$
2. $d = \frac{s_1 \cdot k - z_1}{r} \pmod n$

## Exploit
1. **Signature Extraction:** Extract the two initial signatures from the `ImpersonatorTwoFactory` contract (or via Etherscan internal transaction traces).
2. **Detecting Reuse:** Observe that the `r` value in both signatures is identical (`0xe5648161...`).
3. **Off-Chain Recovery:** Use a Python or JS script implementing the modular arithmetic to recover the private key (`0x10a6891d...`).
4. **On-Chain Execution:**
   - Sign a new payload (`"admin" + "2" + playerAddress`) using the recovered private key.
   - Call `setAdmin` to hijack the contract.
   - Sign another payload (`"lock" + "3"`) to bypass the `FundsLocked` modifier via `switchLock`.
   - Call `withdraw()` to drain the contract.

## Real-World Reference
The most famous example of ECDSA Nonce Reuse in the real world is the **Sony PlayStation 3 Master Key Hack (2010)**. Sony implemented their ECDSA signing algorithm with a hardcoded `k` value instead of a random number generator, allowing hackers to trivially recover the private key used to sign all official PS3 software, permanently breaking the console's security model.
